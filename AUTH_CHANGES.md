# Изменения: Двухэтапная авторизация пользователей

## Дата: 2026-04-05

## Описание
Реализована система двухэтапной авторизации с проверкой телефона и даты рождения. Удалена автоматическая регистрация - все пользователи должны быть предварительно загружены в БД.

---

## Новая логика авторизации

### Вариант 1: Авторизация через emchash (с payload)

**Сценарий:** Пользователь переходит по ссылке `https://max.ru/bot?payload=emchash_abc123`

1. **Поиск по emchash**
   - Ищем контакт в БД по `emchash`
   - ❌ Если не найден → "Пользователь не найден в системе"

2. **Запрос телефона**
   - Текст: "Авторизуйтесь в системе укажите номер телефона"
   - Кнопка: "📞 Отправить свой номер телефона"

3. **Проверка телефона**
   - Сверяем введённый телефон с телефоном из БД
   - ✅ Если совпадает → обновляем `userID` и `chatID`, сообщение "Авторизация успешна!"
   - ❌ Если не совпадает → "Неверный номер телефона. Попробуйте ещё раз."
   - Максимум 3 попытки

### Вариант 2: Авторизация через телефон (без payload)

**Сценарий:** Пользователь отправляет `/start` без параметров

1. **Запрос телефона**
   - Текст: "Авторизуйтесь в системе укажите номер телефона"
   - Кнопка: "📞 Отправить свой номер телефона"

2. **Поиск по телефону**
   - Ищем контакт в БД по телефону
   - ❌ Если не найден → "Пользователь не найден в системе"

3. **Запрос даты рождения**
   - Текст: "Напишите дату Вашего рождения в формате дд.мм.гггг"
   - Пользователь вводит дату текстом

4. **Проверка даты рождения**
   - Сверяем введённую дату с датой из БД
   - ✅ Если совпадает → обновляем `userID` и `chatID`, сообщение "Авторизация успешна!"
   - ❌ Если не совпадает → "Неверная дата рождения. Попробуйте ещё раз."
   - Максимум 3 попытки

## Изменённые файлы

### 1. `internal/storage/tables/contacts.go`

**Добавлено поле `birthdate`:**
```go
type Contact struct {
    UserID    int64
    ChatID    int64
    Phone     string
    Name      string
    EMC       string
    AvatarURL string
    EMCHash   string
    Birthdate string // формат: dd.mm.yyyy
}
```

**Экспортирована функция нормализации:**
```go
func NormalizePhone(phone string) string
```

**Обновлены методы:**
- `Find()` - возвращает birthdate
- `FindByEMCHash()` - возвращает birthdate
- `Save()` - сохраняет birthdate
- `UpdateByPhone()` - обновляет birthdate
- `All()` - возвращает birthdate

### 2. `internal/storage/tables/auth_sessions.go` (новый файл)

**Таблица для отслеживания состояния авторизации:**
```sql
CREATE TABLE auth_sessions (
    user_id INTEGER PRIMARY KEY,
    state TEXT NOT NULL,
    emchash TEXT,
    phone TEXT,
    attempts INTEGER DEFAULT 0,
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);
```

**Состояния (state):**
- `awaiting_phone_emchash` - ожидание телефона (вариант с emchash)
- `awaiting_phone_empty` - ожидание телефона (вариант без payload)
- `awaiting_birthdate` - ожидание даты рождения

**Методы:**
- `Get(userID)` - получить сессию
- `Save(session)` - создать/обновить сессию
- `Delete(userID)` - удалить сессию
- `CleanupOld()` - удалить сессии старше 1 часа

type Service struct {

## Валидация данных

### Формат телефона
- Извлекаются только цифры
- Длина: 10-15 символов
- Нормализация: `8` заменяется на `7` (для РФ)

### Формат даты рождения
- Формат: `dd.mm.yyyy` (например, `01.01.1990`)
- Валидация:
  - День: 1-31
  - Месяц: 1-12
  - Год: 1900-2100
- Принимаются только цифры и точки

---

## Счётчик попыток

- **Максимум попыток:** 3 на каждом этапе
- **При превышении:** Сессия удаляется, отправляется "Пользователь не найден в системе"
- **Сброс счётчика:** При переходе к следующему этапу (от телефона к дате рождения)

---

## Автоматическая очистка

**Старые сессии (>1 час) автоматически удаляются:**
```go
func (table *AuthSessions) CleanupOld() error
```

Рекомендуется запускать периодически (например, каждые 10 минут).

## Оценка ёмкости БД

### Для 500,000 контактов:

**Таблица contacts:**
- Размер записи: ~300 байт
- Данные: ~150 MB
- Индексы: ~27 MB
- **Итого: ~180 MB**

**Таблица auth_sessions:**
- Размер записи: ~100 байт
- Максимум активных сессий: ~1,000 (одновременно)
- **Итого: ~100 KB**

**Общий размер БД: ~200 MB**

SQLite отлично справится с таким объёмом данных.

## Миграция данных

### Автоматическая миграция при запуске:
```sql

CREATE TABLE IF NOT EXISTS auth_sessions (...);
```

### Загрузка контактов через API:
```bash

{
  "user_id": 0,
  "chat_id": 0,
  "phone": "79039076399",
  "name": "Иван Иванов",
  "emc": "EMC001",
  "avatar_url": "",
  "emchash": "abc123",
  "birthdate": "01.01.1990"
}
```

**Примечание:** `user_id` и `chat_id` можно оставить `0` - они будут обновлены при авторизации.
