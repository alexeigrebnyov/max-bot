# max-bot-service — Обзор проекта

## Что это?

HTTP-сервис на Go для работы с ботом в мессенджере MAX (российская платформа для корпоративных коммуникаций). Бот регистрирует пользователей по номеру телефона и позволяет отправлять им уведомления через внешний API.

## Основные возможности

1. **Регистрация пользователей** — бот запрашивает номер телефона при первом контакте
2. **Отправка уведомлений** — внешние системы могут отправлять сообщения по телефону через HTTP API
3. **Управление группами** — автоматическая синхронизация списка групповых чатов
4. **Web UI** — веб-интерфейс для мониторинга сообщений в реальном времени (SSE)
5. **Два режима работы:**
   - **Webhook** — MAX отправляет события на публичный URL
   - **Long Polling** — сервис сам опрашивает MAX API

## Технологический стек

- **Язык:** Go 1.25+
- **БД:** SQLite (modernc.org/sqlite) — хранение контактов и групп
- **HTTP:** стандартная библиотека net/http
- **Rate Limiting:** golang.org/x/time/rate
- **Логирование:** log/slog (структурированные логи)
- **Деплой:** Docker + docker-compose

## Архитектура

Проект следует чистой архитектуре с разделением на слои:

```
cmd/          — точка входа (main.go)
internal/
  ├─ config/  — конфигурация из env
  ├─ storage/ — работа с SQLite (contacts, group_chats)
  ├─ bot/     — бизнес-логика бота и API клиент MAX
  └─ api/     — HTTP сервер и handlers
```

## Основные сценарии использования

### Сценарий 1: Регистрация пользователя
1. Пользователь запускает бота в MAX (`/start`)
2. Бот просит отправить номер телефона (кнопка или текст)
3. Бот сохраняет связку `userID ↔ phone ↔ chatID` в SQLite
4. Теперь внешняя система может отправлять уведомления по телефону

### Сценарий 2: Отправка уведомления
1. Внешняя система делает `POST /send-by-phone` с телефоном и текстом
2. Сервис ищет контакт в БД по телефону
3. Отправляет сообщение пользователю через MAX API

### Сценарий 3: Работа с группами
1. Бота добавляют в групповой чат MAX
2. Сервис автоматически синхронизирует список групп
3. Если бот администратор — отправляет приветствие с кнопкой "ID чата"
4. Внешняя система может отправлять сообщения в группу по `chat_id`

### Сценарий 4: Мониторинг через Web UI
1. Открыть `/admin` в браузере
2. Подключается SSE stream (`/events`)
3. Все входящие сообщения отображаются в реальном времени

## Ключевые таблицы БД

### contacts
```
userID (PK) | chatID | phone | name | emc
```
Хранит зарегистрированных пользователей.

### group_chats
```
chatID (PK) | title | menu_sent
```
Хранит групповые чаты, где есть бот.

## API эндпоинты

**Публичные (с rate limit):**
- `POST /send-message` — отправка по chat/userID
- `POST /send-by-phone` — отправка по телефону

**Служебные (требуют X-API-Key):**
- `POST /refresh-group-chats` — синхронизация групп
- `GET /group-chats` — список групп

**Для интеграции:**
- `POST /send-to-group-by-chatid` — отправка в группу
- `GET /get-messages-by-chatid` — история сообщений
- `POST /add-contact` — добавить контакт
- `GET /contacts` — список контактов

**Для мониторинга:**
- `GET /admin` — web UI
- `GET /events` — SSE stream
- `GET /metrics` — метрики (requests, errors, rate_limits)

## Конфигурация

Все настройки через переменные окружения (см. `.env.example`):
- `BOT_TOKEN` — токен бота MAX (обязательно)
- `WEBHOOK_URL` — если задан → Webhook, иначе → Long Polling
- `PORT` — порт HTTP-сервера (по умолчанию 9003)
- `RATE_LIMIT_PER_MINUTE` — лимит запросов (по умолчанию 60)

## Особенности реализации

1. **Graceful shutdown** — корректное завершение при SIGINT
2. **Rate limiting** — защита от перегрузки API
3. **Нормализация телефонов** — автоматическая замена 8 на 7
4. **Периодическая синхронизация групп** — каждые 5 минут
5. **SSE с ping** — keep-alive каждые 20 секунд
6. **Проверка прав бота** — меню в группе только если бот администратор
